# 로또 추첨기

브라우저에서 여러 이름을 로또 공처럼 섞어 무작위 순서로 뽑는 정적 웹앱입니다. 별도의 회원가입이나 백엔드 서버 없이 실행할 수 있으며, 수동 추첨과 자동 추첨을 모두 지원합니다.

추첨 결과는 브라우저의 Web Crypto API로 결정됩니다. Canvas 애니메이션은 결과와 분리된 시각적 연출이므로 기기 성능이나 공의 화면 위치가 추첨 순서에 영향을 주지 않습니다.

## 주요 기능

- 줄바꿈 또는 콤마로 여러 이름 일괄 입력
- `1~45` 형식의 숫자 범위를 순차 공으로 자동 확장
- 최소 2개, 최대 45개의 공 지원
- 이름당 최대 20자
- 같은 이름을 서로 다른 공으로 중복 등록
- 전체 또는 원하는 개수만 뽑는 비복원 추첨
- 버튼으로 한 공씩 진행하는 수동 모드
- 3~7초 사이의 무작위 간격으로 끝까지 진행하는 자동 모드
- 동일한 공 크기로 중앙과 바깥을 오가는 Canvas 2D 구형 혼합·겹침·배출 연출
- 일부 추첨 완료 후 남은 공이 중력으로 바닥에 쌓이는 정착 연출
- 추첨 순서 누적 표시와 클립보드 복사
- 입력 이름을 브라우저 `localStorage`에 보존
- 기본 음소거 상태의 선택적 효과음
- 모바일·데스크톱 반응형 화면

## 사용 방법

1. `공 이름` 입력란에 이름을 줄바꿈 또는 콤마로 구분해 입력합니다.

   ```text
   민지, 준호
   서연, 민지
   ```

   숫자 공이 필요하면 다른 이름과 섞지 않고 범위식 하나만 입력할 수 있습니다.

   ```text
   1~45
   ```

   위 입력은 `1`, `2`, …, `45`의 45개 공으로 해석됩니다.

2. `전체 추첨` 또는 `일부만 추첨`을 선택합니다. 일부 추첨은 1부터 입력한 공 개수까지 직접 입력할 수 있습니다.
3. `직접 뽑기` 또는 `자동 추첨`을 선택합니다.
4. 필요하면 효과음 토글을 켭니다. 기본값은 음소거입니다.
5. `추첨 시작`을 누릅니다.
6. 수동 모드에서는 `다음 공 뽑기`를 누를 때마다 한 공이 나옵니다.
7. 자동 모드에서는 카운트다운 없이 3~7초 사이에 공이 하나씩 나옵니다.
8. 목표한 개수의 추첨이 끝나면 `결과 복사`로 순서 목록을 복사할 수 있습니다.
9. `처음부터 다시`를 누르면 이름 목록과 현재 설정을 유지한 채 설정 화면으로 돌아갑니다.

예를 들어 이름 45개를 넣고 `일부만 추첨`을 6개로 설정하면 여섯 번째 결과에서 추첨이 완료되며, 나머지 39개는 결과에 포함되지 않습니다.

`모두 지우기`는 입력란과 브라우저에 저장된 이름 목록을 함께 삭제합니다. 페이지를 새로고침하면 이름 목록만 복원되며, 추첨 개수 설정·진행 결과·순서는 초기화됩니다.

## 기술 구성

| 영역 | 기술 |
|---|---|
| UI | React 19, TypeScript |
| 개발·빌드 | Vite |
| 테스트 | Vitest, Testing Library, jsdom |
| 애니메이션 | HTML Canvas 2D |
| 난수 | Web Crypto API |
| 저장 | 브라우저 `localStorage` |
| 효과음 | Web Audio API |

이 프로젝트는 외부 API, 데이터베이스, 분석 도구, 원격 폰트·이미지를 사용하지 않습니다.

## 실행 환경

- Node.js 22 이상 권장
- npm 10 이상 권장
- 최신 안정 버전 Chrome, Safari, Firefox 또는 Edge

현재 자동 검사와 실제 스모크 테스트에 사용한 환경은 Node.js `22.22.1`, npm `10.9.4`, Chromium 기반 브라우저입니다.

## 설치

저장소 루트에서 의존성을 설치합니다.

```bash
npm install
```

## 로컬 개발 서버 실행

```bash
npm run dev
```

터미널에 출력된 주소를 브라우저에서 엽니다. 기본 주소는 다음과 같습니다.

```text
http://localhost:5173
```

기본 포트를 사용할 수 없다면 다른 포트를 지정할 수 있습니다.

```bash
npm run dev -- --port 5174
```

같은 네트워크의 다른 기기에서 테스트해야 할 때만 호스트 바인딩을 엽니다.

```bash
npm run dev -- --host 0.0.0.0
```

이 경우 로컬 네트워크에 개발 서버가 노출될 수 있으므로 신뢰할 수 있는 환경에서만 사용하세요.

## 프로덕션 빌드

TypeScript 검사 후 정적 프로덕션 파일을 `dist/`에 생성합니다.

```bash
npm run build
```

빌드 결과를 로컬 미리보기 서버로 확인하려면 다음 명령을 사용합니다.

```bash
npm exec -- vite preview
```

기본 미리보기 주소는 `http://localhost:4173`입니다. `dist/`는 정적 파일이므로 GitHub Pages, Vercel, Cloudflare Pages 같은 정적 호스팅 환경에 배포할 수 있지만, 서비스별 배포 설정과 자동화는 아직 포함하지 않습니다.

## 테스트와 검증

전체 테스트를 한 번 실행합니다.

```bash
npm test
```

파일 변경을 감시하며 테스트하려면 다음 명령을 사용합니다.

```bash
npm run test:watch
```

TypeScript만 검사하려면 다음 명령을 사용합니다.

```bash
npm run typecheck
```

현재 기준으로 8개 테스트 파일의 54개 테스트가 통과합니다. 주요 검증 범위는 다음과 같습니다.

- 줄바꿈·콤마 파싱과 입력 제한
- 숫자 범위 확장과 형식·방향·개수 오류
- 중복 이름의 개별 공 ID
- 편향 없는 암호학적 난수
- 전체·일부 비복원 추첨과 추첨 개수 경계
- 수동 중복 클릭 방지
- 자동 추첨 일정과 백그라운드 복구
- 3축 운동, 구형 경계, 동일한 공 크기, 중앙 횡단과 완료 후 중력 적층
- 새로고침·재시작 상태 초기화
- 저장·클립보드·효과음 실패 처리

## 프로젝트 구조

```text
.
├── docs/
│   ├── SPEC.md           # 제품·기술 요구사항
│   ├── TASK.md           # 구현 작업과 진행 이력
│   ├── architecture.md   # 컴포넌트·데이터·상태 구조

├── src/
│   ├── components/       # 설정, Canvas 추첨기, 결과, 제어 UI
│   ├── domain/           # 파싱, 난수, 추첨 엔진, 도메인 타입
│   ├── services/         # 브라우저 저장소와 효과음
│   ├── test/             # 공통 테스트 환경
│   ├── App.tsx           # 앱 상태와 브라우저 수명주기 통합

└── vitest.config.ts
```

핵심 추첨 로직은 React와 Canvas에서 분리되어 있습니다. `src/domain/`이 결과와 상태 전이를 담당하고, `LotteryMachine`은 결정된 결과를 시각화만 합니다.

## 데이터와 개인정보

- 이름은 외부 서버로 전송되지 않습니다.
- 입력 원문은 현재 브라우저의 `localStorage`에 평문으로 저장됩니다.
- 공용 기기에서는 사용 후 `모두 지우기`를 눌러 저장된 이름을 삭제하세요.
- 추첨 결과와 진행 상태는 영구 저장하지 않습니다.

## 현재 제한사항

- 공은 최대 45개까지 지원합니다.
- Canvas는 실제 3D 엔진 대신 가상 깊이축을 계산해 2D로 투영하는 시각적 연출입니다.
- 자동 추첨에는 일시정지와 카운트다운이 없습니다.
- 새로고침 후 추첨 결과를 복구하지 않습니다.
- PWA, 다국어, 접근성 전용 대응, 운영 모니터링은 초기 범위 밖입니다.
- Safari, Firefox, Edge는 웹 표준 호환성을 고려했지만 현재 환경에서는 실제 브라우저 스모크 테스트를 수행하지 않았습니다.
