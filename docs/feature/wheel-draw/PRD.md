# 돌림판 추첨기 추가 요구사항

## 1. 개요

### 1.1 배경과 목적

현재 제품은 로또 추첨기 한 종류만 제공한다. 사용자는 후보를 한 번씩 제거하며 순서를 정하는 로또 방식뿐 아니라, 같은 후보가 여러 번 선택될 수 있고 필요할 때마다 반복해서 돌릴 수 있는 전통적인 돌림판 방식도 사용하고 싶어 한다.

이번 기능은 기존 로또 추첨기와 돌림판 추첨기를 한 웹앱에서 선택해 사용할 수 있게 한다. 두 추첨기는 서로 다른 추첨 규칙과 사용자 흐름을 독립적으로 제공하며, 돌림판 추가가 기존 로또 추첨기의 동작에 영향을 주지 않아야 한다.

### 1.2 기대 효과

- 사용 목적에 따라 비복원 로또 추첨과 복원 돌림판 추첨을 선택할 수 있다.
- 같은 후보가 반복 당첨될 수 있는 게임·발표·순서 선택 상황을 지원한다.
- 추첨기별 요구사항이 독립적으로 발전해도 기존 기능의 회귀 위험을 낮춘다.
- 추후 다른 추첨 방식도 기존 추첨기 동작을 변경하지 않고 추가할 수 있다.

## 2. 이해관계자와 사용자

- 의사결정자: 프로젝트 소유자
- 최종 사용자: 설치나 가입 없이 브라우저에서 이름·숫자 목록을 무작위로 선택하려는 사용자
- 사용 환경: 최신 데스크톱·모바일 웹 브라우저

사용자는 공정한 결과, 간단한 설정, 자연스러운 회전 연출과 기존 로또 추첨기의 안정적인 동작을 기대한다.

## 3. 범위

### 3.1 포함 범위

- 로또 추첨기와 돌림판 추첨기 선택
- 추첨기별 직접 진입과 선택 화면 복귀
- 기존과 같은 후보 입력 문법과 검증
- 같은 후보가 반복 당첨될 수 있는 돌림판 복원 추첨
- 사용자가 버튼을 눌러 실행하는 수동 회전
- 목표 횟수 없이 필요한 만큼 반복 회전
- 회전별 결과 이력 누적·복사·비우기
- 자연스러운 회전·감속과 동작 감소 환경 대응
- 구획 이름 축약과 전체 후보 이름 확인
- 기본 음소거인 회전·당첨 효과음
- 후보 입력과 돌림판 설정의 브라우저 저장
- 모바일·데스크톱 반응형 UI
- 기존 로또 기능과 Remote MCP의 비회귀 검증

### 3.2 제외 범위

- 자동 연속 회전
- 목표 회전 횟수 설정과 완료 상태
- 당첨 후보 제거 또는 비복원 모드 선택
- 결과 이미지 저장
- 결과 이력의 새로고침 후 복원
- 서버, 데이터베이스, 계정과 기기 간 동기화
- Remote MCP 도구의 추첨기 종류 선택
- 로또 추첨기의 추첨 규칙·진행 방식·연출 변경
- 기능별 별도 배포

## 4. 기능 요구사항

### 4.1 추첨기 선택

- 기본 주소에서는 로또 추첨기와 돌림판 추첨기를 선택할 수 있는 화면을 표시한다.
- 각 추첨기로 직접 진입할 수 있어야 한다.
- 기능 화면에서 `다른 추첨기 선택`으로 선택 화면에 돌아갈 수 있어야 한다.
- 선택 화면에서 기능으로 진입한 뒤 브라우저 뒤로 가기를 사용하면 선택 화면으로 돌아간다.
- 마지막으로 선택한 추첨기는 선택 화면에서 강조하되 자동으로 진입하지 않는다.
- 처음 사용하거나 저장값이 손상된 경우 어떤 추첨기도 임의로 실행하지 않고 선택 화면을 표시한다.

### 4.2 후보 입력

- 후보 입력은 기존 로또 추첨기와 같은 문법을 사용한다.
- 줄바꿈 또는 콤마로 후보를 구분한다.
- `이름*반복횟수`와 `시작숫자~끝숫자` 문법을 지원한다.
- 유효한 후보는 최소 2개, 최대 45개다.
- 후보 이름은 최대 20자다.
- 같은 이름의 후보를 여러 번 입력할 수 있으며 각각 별도 구획으로 취급한다.
- 오류가 있으면 원인을 한국어로 표시하고 돌림판 시작을 차단한다.
- `입력 비우기`는 돌림판 후보 입력만 삭제하고 로또 입력에는 영향을 주지 않는다.

### 4.3 돌림판 시작과 회전

- 유효한 후보로 돌림판을 시작하면 모든 후보가 동일한 크기의 구획으로 표시된다.
- 사용자가 회전 버튼을 누를 때마다 현재 전체 후보 중 하나를 독립적으로 선택한다.
- 당첨 후보를 돌림판에서 제거하지 않는다.
- 같은 후보가 연속하거나 여러 번 당첨될 수 있다.
- 목표 회전 횟수나 완료 상태를 두지 않고 사용자가 필요한 만큼 반복 회전한다.
- 회전 중에는 추가 회전 입력을 받지 않는다.
- 회전 결과는 회전 시작 시 공정하게 먼저 결정되고 화면 연출은 결과를 변경하지 않는다.
- 안전한 난수를 사용할 수 없으면 결과를 만들지 않고 재시도 가능한 오류를 표시한다.

### 4.4 회전 연출

- 일반 회전은 회전 강도에 따라 3.8~5.2초 동안 6~10바퀴 진행한다.
- 빠르게 회전을 시작하고 자연스럽게 감속해 당첨 구획이 포인터에 정지해야 한다.
- 역회전, 마지막 순간의 부자연스러운 점프 또는 목표 구획 불일치가 없어야 한다.
- 회전 애니메이션은 구현 완료 후 실제 브라우저 테스트에서 자연스러움을 미세 조정한다.
- 동작 감소 환경에서는 장시간·다회전 연출을 생략하고 짧은 전환 후 같은 결과를 표시한다.
- 화면이 느리거나 일시 중단되어도 당첨 결과가 변경되거나 중복 반영되지 않아야 한다.

### 4.5 후보와 결과 표시

- 돌림판 구획에는 공간에 맞게 후보 이름을 말줄임 표시할 수 있다.
- 별도 후보 목록에서 모든 후보의 전체 이름을 확인할 수 있어야 한다.
- 모바일에서도 전체 후보 목록과 결과 이력을 확인할 수 있어야 한다.
- 결과 이력에는 회전 순서와 당첨 후보의 전체 이름을 표시한다.
- 같은 후보가 반복 당첨돼도 각 결과를 별도 항목으로 모두 표시한다.
- 최신 당첨 결과를 명확히 구분한다.
- 사용자는 현재 결과 이력 전체를 순서가 포함된 일반 텍스트로 복사할 수 있다.
- `결과 비우기`는 후보와 설정을 유지한 채 결과 이력만 삭제한다.

### 4.6 효과음

- 돌림판 회전과 당첨 결과에 맞는 효과음을 제공한다.
- 최초 기본값은 음소거다.
- 사용자는 돌림판 화면에서 효과음을 켜거나 끌 수 있다.
- 효과음 선택은 새로고침 후 복원한다.
- 음향 재생에 실패해도 회전과 결과는 정상적으로 처리한다.

### 4.7 저장과 초기화

- 돌림판 후보 원문과 돌림판 설정만 현재 브라우저에 저장한다.
- 로또 후보·설정과 돌림판 후보·설정은 서로 영향을 주지 않는다.
- 결과 이력과 진행 중 회전은 저장하지 않는다.
- 새로고침하면 후보와 설정을 복원하고 결과 이력 없이 설정 화면에서 시작한다.
- `처음부터 다시`는 후보와 설정을 유지하고 결과 이력을 삭제한 뒤 돌림판 설정 화면으로 돌아간다.
- 추첨기 종류를 전환하면 진행 중 회전과 결과 이력을 삭제하되 후보와 설정은 유지한다.
- 저장값이 손상되거나 저장에 실패해도 가능한 현재 기능을 유지하고 사용자가 이해할 수 있는 경고를 표시한다.

### 4.8 기존 로또 비회귀

- 추첨기 선택 화면 추가를 제외한 기존 로또 추첨기의 동작은 변경하지 않는다.
- 로또의 후보 입력·검증·비복원 추첨·수동·자동 진행·재추첨·2D·3D 전환을 유지한다.
- 로또의 효과음·결과 복사·이미지 저장·백그라운드 복구를 유지한다.
- 기존 로또 후보와 설정 저장값을 그대로 복원해야 한다.
- 돌림판 입력·설정·오류가 로또 기능에 영향을 주지 않아야 한다.
- Remote MCP의 도구 계약, 결과와 빌드 경계를 변경하지 않는다.

## 5. 데이터 요구사항

- 후보는 내부 식별자와 사용자에게 표시할 이름을 가진다.
- 같은 이름의 후보도 서로 다른 후보로 취급한다.
- 돌림판 결과는 개별 회전 사건으로 식별한다.
- 하나의 후보가 여러 결과 사건에 반복해서 연결될 수 있다.
- 후보와 설정은 사용자 브라우저에만 보존한다.
- 진행 결과는 화면을 사용하는 동안에만 유지한다.
- 후보와 결과를 외부 서버에 전송하지 않는다.

## 6. 비기능 요구사항

### 6.1 정확성과 공정성

- 결과 정확성이 애니메이션 부드러움보다 우선한다.
- 모든 후보 구획은 회전마다 같은 당첨 확률을 가져야 한다.
- 화면 위치, 프레임 속도와 회전 연출은 결과에 영향을 주지 않는다.
- 빠른 중복 조작과 중복 완료 이벤트가 결과를 두 번 추가하지 않아야 한다.
- 안전한 난수 실패 시 낮은 품질 난수로 대체하지 않는다.

### 6.2 사용성과 접근성

- 모바일과 데스크톱에서 동일한 기능을 제공한다.
- 키보드만으로 추첨기 선택, 설정, 회전, 결과 조작과 설정 복귀가 가능해야 한다.
- 돌림판 회전은 `Space`, 결과 이력을 비우고 재추첨을 준비하는 동작은 `R` 단축키로 제공한다.
- 색상이나 회전만으로 상태와 결과를 전달하지 않는다.
- 구획에서 축약된 이름은 후보 목록과 결과 이력에서 전체 이름을 확인할 수 있어야 한다.
- 동작 감소 환경에서도 기능과 결과 확인에 차이가 없어야 한다.

### 6.3 안정성과 성능

- 후보 2~45개에서 제어와 결과 화면이 반응해야 한다.
- 저성능 환경에서도 결과의 선택·중복 방지·순서를 정확히 유지한다.
- 기능 전환이나 화면 종료 시 진행 중 연출과 음향이 남지 않아야 한다.
- 돌림판 오류가 로또 추첨기를 사용할 수 없게 만들지 않아야 한다.

### 6.4 보안과 개인정보

- 사용자 입력은 명령이나 HTML이 아닌 텍스트로 취급한다.
- 후보와 결과를 외부로 전송하거나 원격 로그에 남기지 않는다.
- 공용 기기에서는 입력 비우기로 저장된 돌림판 후보를 삭제할 수 있어야 한다.

## 7. 우선순위와 단계

| 우선순위 | 범위 |
|---|---|
| P0 | 추첨기 선택, 입력·검증, 복원 추첨, 반복 회전, 결과 선확정, 결과 이력, 기능별 저장 격리, 기존 로또 비회귀 |
| P1 | 자연스러운 회전, 후보 전체 이름 확인, 결과 복사·비우기, 직접 진입·뒤로 가기, 동작 감소 대응, 반응형·키보드 사용 |

| 후속 | 자동 회전, 당첨 후보 제거 옵션, 결과 이미지 저장, 결과 이력 복원, 별도 배포, MCP 추첨기 선택 |

## 8. 성공 기준

- 사용자가 선택 화면에서 로또 또는 돌림판을 선택해 실행할 수 있다.
- 2~45개 후보로 돌림판을 시작하고 원하는 만큼 반복 회전할 수 있다.
- 같은 후보가 연속 당첨될 수 있고 각 결과가 이력에 별도로 남는다.
- 일반 회전은 3.8~5.2초·6~10바퀴 범위에서 자연스럽게 감속해 미리 확정된 후보에 정지한다.
- 결과 이력을 복사하거나 비우고 후보·설정을 유지할 수 있다.
- 새로고침과 기능 전환 후 결과는 초기화되고 후보·설정은 요구사항대로 복원된다.
- 모바일·데스크톱과 동작 감소 환경에서 동일한 결과를 확인할 수 있다.
- 기존 로또 자동 테스트와 핵심 사용자 흐름에 회귀가 없다.
- 기존 로또 저장값과 Remote MCP 계약이 유지된다.
- 전체 자동 검증, 정적 빌드와 기능 경계 검사가 통과한다.

## 9. 미결정 사항

제품 요구사항의 미결정 항목은 없다. 자연스러운 회전의 세부 속도·감속 값은 결과 계약을 바꾸지 않는 범위에서 구현 후 실제 브라우저 테스트로 조정한다.
