# Feature 문서 편집 지침

## 브랜치와 디렉터리 일치

- 현재 Git 브랜치가 `feature/<name>`이면 `docs/feature/<name>/`만 해당 브랜치의 편집 가능한 feature 문서 디렉터리다.
- 작업을 시작하기 전에 현재 Git 브랜치 이름을 확인하고, `feature/` 뒤의 전체 경로가 대상 디렉터리 경로와 정확히 일치하는지 확인한다.
- 현재 브랜치와 일치하는 디렉터리 안에서만 파일을 생성·수정·삭제·이동할 수 있다.
- 현재 브랜치와 일치하지 않는 다른 `docs/feature/` 하위 디렉터리와 파일은 참조용으로만 읽을 수 있으며 변경하지 않는다.
- 현재 브랜치가 `feature/` 형식이 아니거나 일치하는 디렉터리가 불명확하면 `docs/feature/` 하위 문서를 변경하지 않고 사용자에게 대상 경로를 확인한다.

예를 들어 현재 브랜치가 `feature/mcpapp-ux-improvement`이면 `docs/feature/mcpapp-ux-improvement/`만 편집할 수 있고, `docs/feature/remote-mcp/` 등 다른 feature 디렉터리는 이전 작업의 내용을 참고하기 위한 목적으로 사용한다.

## Feature 작업 기준 충돌 처리

- 작업 기준은 요구사항, 스펙, 계약, 설계 결정, 작업 계획, 운영 정책과 그 밖에 구현·검증 방향을 정하는 문서 내용을 모두 포함한다.
- 다른 feature 디렉터리의 작업 기준과 현재 브랜치의 요구사항이 상충하더라도 다른 feature 디렉터리의 문서를 수정하지 않는다.
- 충돌을 발견하면 현재 브랜치에 대응하는 `docs/feature/<name>/OVERRIDES.md`를 생성하거나 갱신해 현재 브랜치에서 우선 적용할 작업 기준을 기록한다.
- `OVERRIDES.md`에는 충돌하는 기존 문서와 항목, 현재 요구사항, 현재 브랜치에서 적용할 기준, 변경 이유와 영향 범위를 명시한다.
- 현재 브랜치에서 작업할 때는 `docs/feature/<name>/` 안의 문서와 `OVERRIDES.md`를 다른 feature 디렉터리의 문서보다 우선한다.
- 같은 디렉터리 안에서도 `OVERRIDES.md`에 명시된 기준이 기존 문서의 상충하는 내용보다 우선한다.
- 이 우선순위는 feature 문서 사이의 작업 기준 해석에 적용하며, 사용자 지시와 상위 `AGENTS.md` 지침을 변경하거나 무시하지 않는다.

## 정책 파일 예외

- 이 `docs/feature/AGENTS.md`는 사용자가 정책 변경을 명시적으로 요청한 경우에만 수정한다.
